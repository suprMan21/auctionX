# S-2FA — Passkeys, backup factors, step-up, two-admin approval

**Status:** Plan, awaiting Boss approval (2026-10-27). Branch `feature/s-2fa`, worktree `.claude/worktrees/s-2fa`.

## Objective

Every account gets a second factor, and passkeys are the main one: Face ID, Touch ID or a security key, built
in-house with WebAuthn. A fresh passkey check ("step-up") is required before a token release, a transfer
completion, an admin price change and admin destructive actions. Admin destructive actions also need a second
admin to approve them. This must land before any real token sale.

## Key design choice: our own "second factor done" marker

Supabase's `aal2` only exists for Supabase's own MFA factors, and we are not using them. So:

- After a password sign-in, the Supabase session is first-factor only. The user then completes a passkey, TOTP or
  recovery code with **our** backend. The backend writes an `mfa_sessions` row keyed on the JWT's `session_id`
  claim, read after `getUser` has verified the token, the same way `readAalClaim` works today.
- A signed-out or revoked Supabase session gets a new `session_id`, so an old marker can never be reused. The row
  also expires on its own after `MFA_SESSION_TTL_HOURS` (default 12).
- The existing gates (`twoFactorGate.ts` for claim and transfer complete, and `adminAuth.ts:124`) switch from
  checking `aal === 'aal2'` to `hasSecondFactor(req)`. They keep the same flags, error codes (`2fa_required`,
  `ADMIN_2FA_REQUIRED`) and security events. The duplicate `isTwoFactorRequired` goes; `featureFlags.ts` keeps
  the only copy.
- **A step-up is a single-use grant, not a time window.** The user passes a passkey check for a named action and
  target. The server returns a random token, valid for 2 minutes, stored hashed and bound to
  user + session + action + target. The protected route requires it in an `X-Step-Up` header and spends it
  atomically through an RPC. A grant for releasing token A cannot be used to release token B.

## Database changes (Ph1: migration `20261027000006_s_2fa_factors.sql`)

All tables have RLS **enabled with no policies** and no anon/authenticated grants (service_role only). Every
SECURITY DEFINER function REVOKEs EXECUTE from PUBLIC, anon, authenticated (Every-Session lesson). All DDL is
idempotent. CHECKs wrap nullable columns in `coalesce`.

```sql
-- Passkeys (one user, many credentials)
CREATE TABLE IF NOT EXISTS public.user_passkeys (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  credential_id text NOT NULL UNIQUE,          -- base64url
  public_key    bytea NOT NULL,                -- COSE
  sign_count    bigint NOT NULL DEFAULT 0,
  transports    text[] NOT NULL DEFAULT '{}',
  aaguid        uuid,
  backed_up     boolean NOT NULL DEFAULT false, -- synced passkey (iCloud / Google)
  nickname      text NOT NULL CHECK (length(btrim(nickname)) BETWEEN 1 AND 40),
  created_at    timestamptz NOT NULL DEFAULT now(),
  last_used_at  timestamptz
);

-- Authenticator app (at most one per user); secret is a KMS envelope, as with the ownership salt
CREATE TABLE IF NOT EXISTS public.user_totp_factors (
  user_id        uuid PRIMARY KEY REFERENCES public.users(id) ON DELETE CASCADE,
  secret_enc     bytea NOT NULL,
  verified_at    timestamptz,                  -- NULL until the first code confirms setup
  last_used_step bigint NOT NULL DEFAULT 0,    -- refuses a code that was already used (replay)
  created_at     timestamptz NOT NULL DEFAULT now()
);

-- Recovery codes (10 per set; generating a new set deletes the old one)
CREATE TABLE IF NOT EXISTS public.user_recovery_codes (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  code_hash  text NOT NULL,                    -- HMAC-SHA256(server pepper, normalised code)
  used_at    timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, code_hash)
);

-- Passkey challenges (single use, 5 min). In the DB, not in memory: App Runner can run more than one instance.
CREATE TABLE IF NOT EXISTS public.mfa_challenges (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  session_id uuid NOT NULL,
  purpose    text NOT NULL CHECK (coalesce(purpose,'') IN ('register','sign_in','step_up')),
  challenge  text NOT NULL,
  action     text,                             -- step_up only
  target_id  text,                             -- step_up only
  expires_at timestamptz NOT NULL,
  used_at    timestamptz
);

-- "Second factor done" for one Supabase session
CREATE TABLE IF NOT EXISTS public.mfa_sessions (
  session_id  uuid PRIMARY KEY,
  user_id     uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  method      text NOT NULL CHECK (coalesce(method,'') IN ('passkey','totp','recovery_code')),
  verified_at timestamptz NOT NULL DEFAULT now(),
  expires_at  timestamptz NOT NULL
);

-- Single-use step-up grants
CREATE TABLE IF NOT EXISTS public.step_up_grants (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  token_hash text NOT NULL UNIQUE,             -- SHA-256 of a random 32-byte token
  user_id    uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  session_id uuid NOT NULL,
  action     text NOT NULL,                    -- 'release' | 'transfer_complete' | 'price_change' | 'admin_approve' | 'factor_remove'
  target_id  text NOT NULL,
  expires_at timestamptz NOT NULL,
  used_at    timestamptz
);

-- Lockout after repeated wrong codes (TOTP and recovery codes; passkeys cannot be guessed)
CREATE TABLE IF NOT EXISTS public.user_mfa_state (
  user_id         uuid PRIMARY KEY REFERENCES public.users(id) ON DELETE CASCADE,
  failed_attempts int NOT NULL DEFAULT 0,
  locked_until    timestamptz
);
```

Atomic RPCs (SECURITY DEFINER, service_role only):
- `consume_mfa_challenge(p_id, p_user, p_session, p_purpose)`: marks it used once and returns it, or nothing if it
  expired or was already used.
- `consume_step_up_grant(p_token_hash, p_user, p_session, p_action, p_target)`:
  `UPDATE … SET used_at = now() WHERE used_at IS NULL AND expires_at > now() … RETURNING id`.
- `use_recovery_code(p_user, p_code_hash)`: same pattern.
- `record_mfa_failure(p_user)` and `clear_mfa_failures(p_user)`: 5 failures lock for 15 minutes.
- Cleanup: an hourly pg_cron job deletes expired challenges, grants and sessions.

**Ph3 migration** (`…_s_2fa_admin_approvals.sql`):
```sql
CREATE TABLE IF NOT EXISTS public.admin_action_approvals (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  action        text NOT NULL,   -- 'tag_reset' | 'account_delete' | 'account_retire' | 'account_suspend' | 'role_change' | 'tag_suspend'
  target_id     text NOT NULL,
  payload       jsonb NOT NULL,  -- exact request body; it runs as approved, never re-read from the requester
  payload_hash  text NOT NULL,
  reason        text NOT NULL CHECK (length(btrim(coalesce(reason,''))) >= 10),
  requested_by  uuid NOT NULL REFERENCES public.admin_users(id),
  requested_at  timestamptz NOT NULL DEFAULT now(),
  decided_by    uuid REFERENCES public.admin_users(id),
  decided_at    timestamptz,
  decision      text CHECK (decision IS NULL OR decision IN ('approved','rejected','cancelled','expired')),
  executed_at   timestamptz,
  result        jsonb,
  expires_at    timestamptz NOT NULL,          -- 24 h
  CHECK (decided_by IS NULL OR decided_by <> requested_by)
);
-- At most one open request per (action, target)
CREATE UNIQUE INDEX IF NOT EXISTS admin_action_approvals_open
  ON public.admin_action_approvals (action, target_id) WHERE decision IS NULL;
```

No existing table or column is changed (schema-lock safe). `database.types.ts` is regenerated after each migration.

## API endpoints

All are under `/api/v1/auth/mfa` and use `requireAuth` unless noted, with a rate limit of 10/min per user on
the verify endpoints. Responses use `{ success, data, error }` and Zod `.strict()` bodies.

| Method | Path | Purpose | Extra requirement |
|---|---|---|---|
| GET | `/status` | Factors on the account (passkey nicknames + dates, TOTP yes/no, recovery codes left), is this session verified, is enrolment required | — |
| POST | `/passkeys/register/options` | Registration options + challenge | Session verified, **or** the account has no factors yet (first enrolment) |
| POST | `/passkeys/register/verify` | Saves the passkey. The first factor also returns 10 recovery codes (shown once) and marks the session verified | same |
| POST | `/sign-in/options` | Passkey assertion options for this session | — |
| POST | `/sign-in/verify` | Body: `{ passkey }` \| `{ totp }` \| `{ recoveryCode }`. Writes `mfa_sessions` | lockout applies |
| POST | `/step-up/options` | `{ action, targetId }` → assertion options | Session verified |
| POST | `/step-up/verify` | Assertion → `{ stepUpToken, expiresAt }` | **Passkey only** (see open question 2) |
| POST | `/totp/setup` | Returns the secret + otpauth URI (QR made in the browser) | Session verified |
| POST | `/totp/confirm` | First code sets `verified_at` | — |
| POST | `/recovery-codes/regenerate` | New set of 10, the old set is void | Session verified |
| PATCH | `/passkeys/:id` | Rename | Session verified |
| DELETE | `/passkeys/:id`, `/totp` | Remove a factor. **Refused if it is the last one.** | Step-up (`factor_remove`) |

Changed routes:

| Route | Change |
|---|---|
| `POST /nfc/release` | `requireSecondFactor` + `requireStepUp('release', body.tagId)`. Typed RELEASE stays. |
| `POST /nfc/transfer/:id/complete` | Existing gate moves to the marker + `requireStepUp('transfer_complete', :id)` |
| `POST /nfc/claim`, `/transfer/initiate`, `/transfer/:id/cancel`, `/:tagId/disclosure`, `/reissue-request*` | `requireSecondFactor` (mandatory 2FA; no step-up) |
| `PUT/POST /admin/pricing*` | `requireStepUp('price_change', …)` |
| `verifyAdminAuth` | Checks the marker instead of `aal2` |

Flags (all default off, same reader pattern in `featureFlags.ts`):
- `FEATURE_REQUIRE_2FA`: token routes refuse a session without a verified second factor (exists; rewired).
- `FEATURE_REQUIRE_ADMIN_2FA`: admin routes (exists; rewired).
- `FEATURE_REQUIRE_STEP_UP`: step-up headers enforced (new).
- `FEATURE_ADMIN_TWO_PERSON`: Ph3 (new).

New env: `WEBAUTHN_RP_ID` (staging `d1bwev65w7rqzl.cloudfront.net`), `WEBAUTHN_RP_NAME` ("Authentic Materials"),
`WEBAUTHN_ORIGINS` (comma list), `MFA_SESSION_TTL_HOURS`, `MFA_RECOVERY_PEPPER` (1Password → App Runner literal).
The TOTP secret uses the existing KMS envelope pattern from `lib/ownership/ownershipProof.ts`.

Security events (`securityEvent.ts`, strict enum, no free text): `auth.mfa_enrol`, `auth.mfa_remove`,
`auth.mfa_verify` (method, result), `auth.mfa_lockout`, `auth.step_up` (action, result),
`auth.recovery_code_used`. These are user events, so they go to CloudWatch, not `audit_logs`. Admin factor events
also go to `audit_logs`.

Emails (transactional, via the existing Postmark path; they never block the action): a factor added, a factor
removed, a recovery code used (with the number left), and new recovery codes generated.

**Ph3 endpoints** (admin router, `FEATURE_ADMIN_TWO_PERSON`):

| Method | Path | Purpose |
|---|---|---|
| (existing) | token reset / suspend, account suspend / retire / delete / role change | With the flag on, these return `202 { approvalId }` instead of acting; the payload is stored as is |
| GET | `/admin/approvals?status=` | Queue (Needs attention badge) |
| POST | `/admin/approvals/:id/approve` | Different admin, same permission as the action, plus step-up (`admin_approve`). Runs the stored payload and records the result |

The approval wrapper applies only when the caller's role is `admin` or `support`. A `super_admin` call runs at once,
as today. Actions that are already super_admin-only (account retire and delete, staff role change) are therefore
unaffected; in practice, the rule covers **token reset, token suspend and account suspend** by the daily admins.

### super_admin hardening (Ph1 backend, Ph2 screens)

- **Hardware key only.** A super_admin may sign in and step up only with a passkey that is **not synced**
  (`backed_up = false`, i.e. a YubiKey, not iCloud or Google). It has no authenticator app; recovery codes only.
- **Shorter session.** The second-factor marker lasts 1 hour for super_admin (12 hours for everyone else).
- **Loud.** Every super_admin sign-in and every super_admin action sends an email alert to Boss's daily address and
  a `auth.break_glass` security event, as AWS does for root sign-ins.
- **Every action by super_admin needs a step-up**, not only the destructive list.
| POST | `/admin/approvals/:id/reject` | With a reason |
| POST | `/admin/approvals/:id/cancel` | Requester only |

Both the request and the decision are written to `audit_logs` before anything runs (fail closed).

## Test plan

**Backend unit (vitest):**
- **Passkey register/verify:** wrong origin or RP ID, a used challenge, an expired challenge, a challenge from
  another session, a counter going backwards, and an unknown credential are all refused.
- **TOTP:** an accepted code is refused if reused (`last_used_step`); a ±1 step window is accepted; setup is not
  live until confirmed; the secret never appears in a response or log.
- **Recovery codes:** single use; normalisation (case, dashes, spaces); a used code is refused; regenerating voids
  the old set; the response includes the number of codes left.
- **Lockout:** the 6th wrong code within 15 min is refused even when it is right; it unlocks after 15 min.
- **Session marker:** another user's `session_id` is refused; an expired row is refused; a row from a revoked
  session is refused.
- **Step-up:** works once; a second use is refused; a wrong action, target, user or session is refused; an expired
  grant is refused; the header is missing → `STEP_UP_REQUIRED`.
- **Gates:** each flag on/off × verified/unverified, for every route in the tables above. Release still needs the
  typed RELEASE as well.
- **Last-factor rule:** removing the only factor is refused, and removal needs a step-up.
- **Public-fields rule:** `/status` never returns a public key, a secret or a code hash.
- **Columns:** the schema drift test covers the new `.from()` chains.

**Live SQL (`supabase/tests/s_2fa_live.sql`, BEGIN … ROLLBACK, dry run before `db push`):**
- RLS is on with no policies.
- anon and authenticated get 42501 on every table and RPC (and a `/rest/v1/rpc` curl probe).
- `consume_*` RPCs are single use under concurrency (two calls → one row).
- CHECKs refuse NULL purpose and NULL method.
- Ph3: `decided_by = requested_by` is refused; a second open request for the same target is refused.

**Frontend (vitest + Testing Library):**
- The StepUpDialog retries with the header and handles cancel and error.
- Recovery codes are shown once and can't be continued past without confirmation.
- A route guard redirects in each state.
- The admin guard prompts instead of signing out on `ADMIN_2FA_REQUIRED`.
- jest-axe on every new page and dialog.
- No "WebAuthn" or "AAL" in the copy.
