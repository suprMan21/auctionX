## Decisions taken with Boss (2026-10-09)

1. **Re-issue = replace a chip that is coming loose, BEFORE it falls off.** Same owner, new chip. Requester must be
   the tag's registered owner at request time AND at fulfilment.
2. **Lost / fallen-off chips are NOT replaced.** Boss: "if it comes off we will not replace it. then someone could
   just take the chip and say oh it fell off send a replacement."
3. **Proof at request time:** a live, verified tap of the old chip by the owner + photos taken with the web app's live
   camera capture (no gallery upload). Boss: "that way we know its real and still scans."
4. **Payment is web only** — the website pay page, linked from an email to the account address and from the token page.
   Never in the phone app (no app store fees).
5. **Pay first, then fulfil.** Approve → owner pays $10 on the web → webhook marks PAID → admin picks an ENROLLED chip
   and clicks Fulfil → Ph1 `admin_reset_token` runs. Nothing goes through unpaid…
6. **…unless an admin waives the fee** on approval with a typed reason (→ WAIVED, no Stripe). Stopgap until Ph3 vouchers.
7. **Owner override: dropped from Ph2.** Token moves only via a real transfer or a same-owner re-issue. Revisit in
   S-ADMIN2 (accounts / identity) if at all. Same stolen-property concern as (2).
8. Approved-but-unpaid requests do not expire in Ph2 (owner can cancel; Ph3 sweep may add an expiry).

## Design

### M1 migration `20261009000001_s_admin1_reissue.sql` (idempotent, additive only)

`reissue_requests` new optional columns (status CHECK untouched):
- `payment_status TEXT NULL` CHECK IN (`AWAITING_PAYMENT`, `PAID`, `WAIVED`)
- `tap_session_id UUID → nfc_tap_sessions` (the proof tap)
- `photo_keys TEXT[]` (private S3 keys, 1–3)
- `paid_at`, `fulfilled_at TIMESTAMPTZ`, `fulfilled_by UUID → users`, `new_tag_id UUID → nfc_tags`
- `review_reason TEXT`, `waive_reason TEXT`
- Unique partial index on `stripe_payment_intent_id` where not null.

Lifecycle: `PENDING` → (approve) `APPROVED` + `AWAITING_PAYMENT` → (webhook) `PAID` | (approve+waive) `WAIVED`
→ (fulfil) `fulfilled_at` set. `PENDING` → `REJECTED` (no charge). Owner may cancel while PENDING or
AWAITING_PAYMENT (→ `CANCELLED`; open PI cancelled in Stripe).

New SECURITY DEFINER RPCs, service_role only, re-check `manage_nfc`, audit row inside (Ph1 pattern):
- `admin_review_reissue(p_request, p_admin, p_approve, p_waive, p_reason)` — refuses if requester ≠ current owner or
  tag not ACTIVE/SUSPENDED.
- `admin_fulfil_reissue(p_request, p_new_tag, p_admin, p_reason, p_custody_id, p_ownership_id, p_tag_ref, p_salt_enc)` —
  requires PAID/WAIVED and not fulfilled; re-checks requester = owner; runs the reset in the same transaction and
  stamps `fulfilled_*` + `new_tag_id`. Live test forces a failure at the last statement.

No anon/authenticated grants; probe 42501 live.

### Backend
- **Owner request** (`POST /nfc/reissue-request`, tightened): requires current owner, tag ACTIVE, a verified
  `nfc_tap_sessions` row for this tag by this user within 10 min (single use), and 1–3 uploaded photo keys.
  `POST /nfc/reissue-request/photo-url` → presigned PUT to a **private** prefix
  `reissue-evidence/<userId>/<uuid>.jpg` (image/jpeg, size-capped); keys must match the caller's prefix.
- **Owner:** `GET /nfc/reissue-requests/mine`, `POST /nfc/reissue-requests/:id/pay` (PI `kind=token_reissue_fee`,
  metadata `reissue_request_id`, idempotencyKey `token-reissue-fee-<id>`, PI id stored before return, returns
  clientSecret), `POST /nfc/reissue-requests/:id/cancel`.
- **Admin** (`routes/admin/reissue.ts`, `manage_nfc`): `GET /admin/reissue-requests?status=` (photos as short-lived
  presigned GETs), `POST …/:id/approve {reason, waive?}`, `POST …/:id/reject {reason}`,
  `POST …/:id/fulfil {newTagId, confirmSerialSuffix, reason}`.
- **Webhook:** new `kind=token_reissue_fee` branch → bind to the request's stored PI id (mismatch = forbidden),
  conditional `AWAITING_PAYMENT → PAID`, replay = 200, 500 on apply failure (Locked). Kinds cross-checked so a
  transfer PI can never pay a re-issue or vice versa. Same endpoint + secret (`STRIPE_TOKEN_FEE_WEBHOOK_SECRET`).
- **Confirm by serial suffix** (all chips in the lot share UID suffix `…936980`): reset + fulfil confirm on the last
  6 of the chip serial; v1 chips (no serial) fall back to the full UID.
- **Emails** (transactional, never block; `transferEmails.ts` pattern): approved (link to the web pay page),
  waived/ready, rejected (with reason), fulfilled.
- Security events: `admin.reissue_action`; `payment.webhook` carries the reissue id.

### Frontend (web)
- Owner (not advertised): after a verified tap of their own token → "Chip coming loose?" link → live camera capture
  (1–3 stills, no file picker) → submit. Token page shows request status + "Pay $10" (`PaymentForm.tsx`) + Cancel.
  `/tokens/reissue/:id/pay` is the email link target.
- Admin: `/admin/reissue-requests` queue (status filter, photos, tap time, approve / approve-and-waive / reject /
  fulfil dialogs with typed reasons, ENROLLED chip picker, serial confirmation).
