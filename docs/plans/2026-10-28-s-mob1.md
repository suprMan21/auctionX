# S-MOB1 — Creator app: sign-in, passkeys, secure session, version gate

**Status:** approved by Boss 2026-10-28 (sign-up on the web with a link back to the app) · **Date:** 2026-10-28 · **Backlog:** S-MOB1 (Notion `4073baf696648112aed2e5e1ca91feec`)
**Source:** DR-21 v1.1 (`projectClaude/reports/DR-21 Flutter passkeys and step-up.md`) · Locked decisions 2026-10-28:
app is Creator-only (sealing + video), every transaction on the web, passkeys at launch, Corbado `passkeys` behind
`PasskeyClient`, production RP ID `authentic-materials.com`.
**Launch target (Boss 2026-10-28):** testers first (TestFlight + Play internal testing) against staging; public store
release with S-LAUNCH1.

## Objective

Turn `mobile/` from the marketplace-era app into the token-first Creator app shell: a Creator signs in with password +
second step (passkey, authenticator code or backup code), can set up and manage those methods in the app, and the
session is stored securely. Ends with a tester build on TestFlight and Play internal testing. Sealing itself is S-MOB2.

## What exists today (read 2026-10-28)

- 15.7k lines of Dart, package `auctionx_mobile`, Riverpod + go_router + Dio + supabase_flutter 2.8.
- Features: auth (password only), browse, minting (NFT), seller (batch registration, QR), video_proof, nfc (legacy
  `GET /nfc/:tagId`, `/nfc/by-uid`), activity, profile, onboarding. Most are marketplace-era and go.
- Supabase session in SharedPreferences (supabase_flutter default, unencrypted). Keys hard-coded in `api_constants.dart`.
- iOS target 13, entitlements = NFC TAG only. Android minSdk 26, targetSdk 34. Bundle / app ID `com.authenticmaterials.tags`, team `F5F52345D2`.
- Android manifest: `autoVerify` sits on the `auctionx://verify` custom-scheme filter; it belongs on the https filter.
- Toolchain on Boss's Mac: Flutter 3.44.0 / Dart 3.12, Xcode 27.1, CocoaPods.
- Backend `/api/v1/auth/mfa/*` is complete for the web (status, sign-in options/verify, passkey register, TOTP,
  backup codes, step-up, recovery). No app-version check exists. `WEBAUTHN_ORIGINS` unset → only `https://<rp-id>`.
- `/.well-known/*` on both sites returns the SPA's HTML with 200 (no association files).

## Decisions this plan assumes (Boss to confirm at review)

1. **No sign-up in the app; the website links back (Boss 2026-10-28, approved).** "Create an account" and "Become a
   creator" open the web app with a fixed `?from=app` flag. The flag survives sign-up, email confirmation and the
   creator request; **only when the flag is present** (the person started in the app), each finish screen shows **Open the Authentic Materials app**, a universal link / App Link to
   `https://<web host>/app/open` that opens the app at sign-in (email prefilled when known). Rules: the link back is a
   fixed path, never a URL taken from a parameter (no open redirect); it never carries a token or session; if the
   app isn't installed, `/app/open` is a plain web page with the TestFlight / Play testing links. Keeps the app small
   and avoids Apple's in-app account-deletion rule (it applies to apps that create accounts).
2. **Non-creators who sign in** see "This app is for creators" with a link to Become a creator on the website, and a
   Sign out button. No other screens.
3. **Email recovery stays on the website at launch.** The app's "Can't use any of these?" links to `/recover`.
4. **Rename the Dart package** `auctionx_mobile` → `authentic_materials` during the reset (imports change anyway).
5. **One build, two environments** via `--dart-define-from-file=env/staging.json|prod.json` (no Xcode flavors).
   The iOS entitlement lists both `webcredentials:` domains; the RP ID is chosen at runtime from config.

## Phases (one session each)

### Phase A — reset + foundations (M0)

Mobile:
- Delete `features/minting`, `features/browse`, `features/seller`, `features/video_proof`, `features/activity`,
  `features/onboarding`, `features/nfc/presentation` + legacy NFC data sources, their generated files and routes.
  Keep `nfc_service.dart` (low-level reader) for S-MOB2. Drop unused deps (`hive*`, `video_compress`, `dartz`, …;
  keep `camera`, `permission_handler`, `nfc_manager`, `share_plus` for S-MOB2).
- Rename package; `pubspec.yaml` version `0.1.0+1`.
- `lib/core/config/app_config.dart`: `ENV`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `API_BASE_URL`,
  `WEB_BASE_URL`, `RP_ID` from `String.fromEnvironment`; fail fast if missing. `env/staging.json` committed (public
  values only); `env/prod.json` placeholder. Fixes the stale-key problem (memory: mobile hardcodes the key).
- `lib/core/storage/secure_session_storage.dart`: supabase_flutter `LocalStorage` + `GotrueAsyncStorage` on
  `flutter_secure_storage` 11.x (iOS `first_unlock_this_device`; Android default cipher). First-launch cleanup clears
  leftover keychain items (iOS keeps them across uninstall).
- Android: `minSdk 28`, `targetSdk` = Play's current requirement (check at build), `allowBackup=false` (or
  data-extraction rules excluding secure storage), move `autoVerify` to the https filter, drop the `auctionx://` scheme.
- iOS: deployment target 16 (Podfile + project), Associated Domains entitlement
  `webcredentials:` + `applinks:` for `authentic-materials.com` and `d1bwev65w7rqzl.cloudfront.net` (keep NFC TAG).
- Android: verified App Link intent filter for `https://<both hosts>/app/open` (`autoVerify`).
- Deep-link handling (`app_links`): `/app/open` → sign-in screen, optional `email` hint only; anything else ignored.
- `api_client.dart`: `X-App-Version` (from `package_info_plus`), readable `User-Agent`
  (`AuthenticMaterials/0.1.0 (iOS 18.1)`), house-envelope parsing that keeps `reason`, interceptor that routes
  `app_update_required` to the update screen.
- Update-required screen (store link per platform; TestFlight / Play link while testing).

Backend:
- `GET /api/v1/app-config` (public, no auth): `{ minVersion: { ios, android }, webBaseUrl }` from env
  `APP_MIN_VERSION_IOS` / `APP_MIN_VERSION_ANDROID` (default `0.0.0`). No private fields (test).
- `middleware/appVersionGate.ts`: if `X-App-Version` + `X-App-Platform` are present and below the minimum →
  426 `{ success:false, reason:'app_update_required' }`. No header (the website) → pass. Malformed header → refuse.
  Mounted on `/auth/mfa` and the token routes.

Frontend (static files only, both builds):
- `frontend/public/.well-known/apple-app-site-association` (`webcredentials` apps + `applinks` details for
  `F5F52345D2.com.authenticmaterials.tags`, components `/app/open*` only) and `assetlinks.json`
  (`delegate_permission/common.get_login_creds` + `delegate_permission/common.handle_all_urls`, SHA-256 of debug +
  upload + Play signing keys).
- `scripts/deploy-frontend.sh`: upload both with `Content-Type: application/json` (AASA has no extension, so `s3 sync`
  would guess wrong); verify through CloudFront after deploy (HTTP 200, JSON, no redirect).
- Test: both files exist, parse as JSON, carry the right app IDs; public build still makes no API call.

### Phase B — sign-in second step (M1)

- `lib/features/mfa/data/mfa_api.dart`: typed client for `/status`, `/sign-in/options|verify`, plus models (freezed)
  mirroring `frontend/src/features/security/api/mfaApi.ts` schemas.
- `lib/features/mfa/data/passkey_client.dart` (interface) + `corbado_passkey_client.dart` (`passkeys` 2.23.x, no
  Corbado backend). Wrapper fills `transports: []` on `allowCredentials` (#322), maps platform errors to our own
  closed set and logs the raw error (#323). Fake implementation for tests.
- Router state machine (go_router `redirect`): update required → signed out → **no marker** → second factor;
  `enrolmentRequired` → setup; account not Creator → creator gate; else home. Account type read from the user's own
  `users` row (RLS own-row select, `account_type` only).
- Web app (staging build only; the public site stays landing-only): keep a fixed `from=app` flag through
  `/register` → email confirmation (`emailRedirectTo` carries the flag) → `/settings/account-type`; only when the flag is set, each finish
  screen shows **Open the Authentic Materials app** → `/app/open`. New `/app/open` page: "Opening the app…" plus
  tester store links when the app isn't installed. Tests: flag survives each step; no flag = no app button (web-only sign-ups never see it); no parameter can change the
  link target; no token in the link.
- Screens: Sign in (password; "Create an account" + "Forgot password" open the web app with `from=app`), Second factor (passkey
  button first; "Use authenticator code" with `AutofillHints.oneTimeCode` + Android `2faAppOTPCode`; "Use a backup
  code" with no autofill hint; lock-out message from `codeEntryLockedUntil`; "Can't use any of these?" → web
  recovery), Creator gate, Home shell (Seal tab placeholder "Coming soon", Security, Account / Sign out).

### Phase C — manage methods (M3) + tester builds (M4 prep)

- Security screen: passkeys (name, synced, last used, "usable from" during cool-off), authenticator app, backup codes left.
- Add a passkey (register options → OS sheet → verify, nickname); set up authenticator app (`otpauth://` button +
