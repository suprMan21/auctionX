## 1. Migration `20261028000003_seal_code.sql` (additive, idempotent)

- `nfc_tags.seal_code TEXT` (nullable), CHECK `^[0-9A-HJKMNP-TV-Z]{8}$` (stored without hyphen), unique index.
- `nfc_chip_names.seal_code TEXT` (same CHECK, unique): the code is reserved with the name, before any chip write.
- `gen_seal_code()`: 8 chars from `extensions.gen_random_bytes` (byte & 31 → uniform over 32), never derived from key material.
  service_role only (REVOKE from PUBLIC, anon, authenticated).
- `reserve_chip_identity(sig, name, actor) RETURNS TABLE(name, seal_code)`: calls the existing `reserve_chip_name`, then gives the
  reservation a seal code if it has none (a re-run of the same chip gets the same code back). Collision → retry loop.
  The old `reserve_chip_name` is kept unchanged, so the currently deployed backend keeps working during the deploy gap.
- `nfc_tags` BEFORE INSERT trigger: if `seal_code` is NULL, take it from the bound reservation (chip_name + fingerprint), else generate one.
  So every new tag gets a code, even through an enroll path that sends no name.
- Write-once: `nfc_tags_identity_write_once` re-created with the same body plus `seal_code` (cannot change or be cleared once set).
- Backfill: every `nfc_tags` row with no code (chip_001, chip_004, chip_, retired chip_002/003 and any others); matching
  `nfc_chip_names` rows get the same code. The retired-freeze trigger does not cover seal_code, so retired rows can be backfilled.
- Reads: anon has no `nfc_tags` row policy (owner-read only since 2026-09-18), so anon cannot read the column; live SQL checks it.
  `public_tag_provenance` is NOT changed (the seal code goes out through the backend only).

Live SQL `supabase/tests/seal_code_live.sql` (BEGIN … ROLLBACK): format, unique, write-once (change + clear refused), backfill
complete, reserve idempotent per fingerprint, enroll copies the reserved code, anon/authenticated cannot execute the functions or
read the column. Dry run through `supabase db query --linked -f` before `db push`; Claude hands Boss the SQL if the classifier
blocks staging writes.

## 2. Backend

- `POST /nfc/enroll/reserve-name` → calls `reserve_chip_identity`, returns `{ name, auto, sealCode }` (display form `XXXX-XXXX`).
- `POST /nfc/tap` (valid) adds `sealCode` (display form, or null if a row somehow has none) and `checkedAt` (server ISO time,
  taken after the SUN check). Invalid taps unchanged: no seal code, nothing about the token.
- `GET /nfc/mine` adds `sealCode` (token detail reads this list).
- `lib/sealCode.ts`: `formatSealCode`, one regex shared by tests.
- Tests: tap response no-private-fields test extended (no serial, UID, owner, chip name; sealCode present and well-formed);
  reserve returns sealCode; mine returns sealCode; failed tap has no sealCode.

## 3. Encoder (`tag-encoder`)

- `reserve_name` returns name + seal code (new `Reservation` type); the fake registry mirrors it; the seal code is written to the
  local audit ledger and printed after the encode. No chip-write change. Unit tests only (no real encode, conserve chips);
  the next real encode is recorded in the verification doc.

## 4. Web

- `components/seal/SealBadge.tsx` + `seal.css`: moved out of `components/home`, class names unchanged but scoped to the
  component (`.sealbadge`, `.sealspin`) instead of `.am-home`. Home imports from the new place. Glow 3.0 s.
  Seal code drawn in bundled IBM Plex Mono (`@fontsource/ibm-plex-mono` 600 latin, self-hosted, no CDN).
  New prop `state: 'verified' | 'sealed'`: sealed = still, slightly muted, no glow, no spin.
- `TokenVerifyPage` (Cinema theme on this page only, `data-theme="cinema"` wrapper; the DS stylesheet is already global
  because App imports HomePage):
  - **Verified**: a tap this page just made (not one read back from the tab cache), for 90 s counted from when the server's
    answer arrived (`checkedAt` is shown, but elapsed time uses the phone's own clock so a wrong device clock cannot extend or
    shorten the window). 88 px animated seal, "Genuine seal", seal code, "Checked by tap · N s ago" and the viewer's clock.
    Ends by itself (WCAG 2.2.2): switches in place to Sealed with "Tap the seal again to check" (G3, no auto re-check).
  - **Sealed**: a refresh, a sign-in round trip, or after the window. Still seal, "Tap the seal to check", never "Verified".
  - Reduced motion: no spin/glow; clock and "N s ago" still update; the outcome is announced as text (heading focus kept).
  - Failed, unknown, error, no-tap views: new look, no seal drawn.
- My Tokens + token detail: small Sealed seal with the code (no live cues).
- `lib/copy.ts` collector strings → seal language (G1). Staff/admin screens untouched. No em dashes, no BPL-9 claims.
- Rules kept: never show serial / UID / chip name / tagId next to the seal; tapSession never in a link or image.
