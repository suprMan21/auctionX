## Objective

Give admins one console to inspect every tag and act on it safely: suspend/unsuspend, an **atomic token reset** that
replaces the non-atomic `/nfc/replace`, and an approval queue for owner re-issue requests with the $10 charge. Every
action needs a typed reason and leaves an append-only audit row.

## Scope note (corrects my earlier summary)

Users/roles is **S-ADMIN2**, not S-ADMIN1. The stuck-payment queue is assigned to S-ADMIN1 by the Locked decision but to
S-ADMIN2 by `TODO.md` / CLAUDE.md; pricing + vouchers is "S-ADMIN1/2". This plan puts both in **Phase 3** (see Q2).

## Phase 1 detail

### Authorization (Q1)

One gate for all token-admin actions: **`admin_users` (active) whose role has `manage_nfc`**, using the existing
`verifyAdminAuth` + `requirePermission('manage_nfc')`. `isStaff()` (users.role) is removed from enroll/precheck/replace.
Why: the spec's AC2 says "admin + manage_nfc"; `admin_users` already has `session_version` revocation + rate limits;
two gates are how we got a mismatch. Consequence: the encoder's staff account and Boss's account must be `admin_users`
rows with a `manage_nfc` role (seeded by migration for the known staging UUIDs, see M2).

### Database changes

**M1 `20261005000001_admin_permission_manage_nfc.sql`** (own file — enum add can't be used in the same transaction):
```sql
ALTER TYPE admin_permission ADD VALUE IF NOT EXISTS 'manage_nfc';
```

**M2 `20261005000002_s_admin1_token_admin.sql`** (optional fields only; no renames/retypes):
- `admin_roles`: insert role `admin` (`view_users, view_audit_logs, manage_nfc`) `ON CONFLICT DO NOTHING`; append
  `manage_nfc` to `super_admin`. Ensure super_admin `2b3f1532…` has an active `admin_users` row (verify first; insert if missing).
- `nfc_tags` new nullable columns: `suspended_at`, `suspended_reason`, `retired_at`, `retired_reason`,
  `replaced_by_tag_id UUID REFERENCES nfc_tags(id)`, `destruction_status TEXT CHECK (IN ('PENDING','DESTROYED'))`.
- **Retired-chip guard (AC6):** `BEFORE UPDATE` trigger on `nfc_tags`: if `OLD.lifecycle_status = 'RETIRED'`, reject any
  change to `lifecycle_status`, `current_owner_id`, `item_id`, `linked_item_id`, `sdm_key_version`. Encoder precheck already refuses RETIRED.
- **Append-only audit (AC7):** `BEFORE UPDATE OR DELETE` trigger on `audit_logs` → `RAISE EXCEPTION`. (Check nothing
  currently updates/deletes `audit_logs` before adding — grep.)
- **`admin_reset_token(p_old_tag uuid, p_new_tag uuid, p_admin uuid, p_reason text, p_proof_hash …, p_ownership_id …)`**
  `SECURITY DEFINER`, `SET search_path = public`. In one transaction: `SELECT … FOR UPDATE` both tags; assert old is
  ACTIVE/SUSPENDED with an owner and new is ENROLLED; move owner/item/disclosure to new tag (ACTIVE); old tag → RETIRED,
  `retired_at/reason`, `replaced_by_tag_id`, `destruction_status='PENDING'`, owner null; insert `ownership_transfers`
  (REISSUE, COMPLETED, 0 fee); stale old proofs + insert the new proof; insert `audit_logs` row. Returns the new tag id.
  The proof is **minted in Node first** (salt key lives in the backend) and passed in, matching today's
  "mint before any write" rule. `REVOKE ALL … FROM PUBLIC, anon, authenticated; GRANT EXECUTE … TO service_role`.
- **`admin_set_tag_suspension(p_tag uuid, p_suspend bool, p_admin uuid, p_reason text)`**: ACTIVE↔SUSPENDED only,
  sets/clears `suspended_*`, writes audit row; same grants. SUN counter untouched.
- Grants check per lesson: no new table, so no new default grants; verify the two functions return 42501 for the
  publishable key via `/rest/v1/rpc/...`.

Apply with `supabase db push --linked` (M1 then M2), regenerate types with the `sed '/^<claude-code-hint/d'` strip,
copy to frontend.

### API endpoints (all under `/api/v1/admin/tags`, `verifyAdminAuth` + `adminRateLimit` + `requirePermission('manage_nfc')`)

| Method | Path | Purpose |
|---|---|---|
| GET | `/admin/tags` | Inventory: filter `lifecycle_status`, UID suffix (last 4), item, creator, `sdm_key_version`, date range; paginated |
| GET | `/admin/tags/:tagId` | Detail: lifecycle timeline (transfers), custody chain, recent taps (`verification_events`), Ownership ID status, owner as **internal account ref only** (user id, no email/name). Never `aes_key_enc`, salts or Receipts (AC8) |
| POST | `/admin/tags/:tagId/suspend` | `{ reason }` (zod, min 10 chars) |
| POST | `/admin/tags/:tagId/unsuspend` | `{ reason }` |
| POST | `/admin/tags/:tagId/reset` | `{ newTagId, reason, confirm: tagUidSuffix }` → mint proof → RPC |

## Phase 2 outline (re-issue queue)

`GET /admin/reissue-requests`, `POST /admin/reissue-requests/:id/approve` (creates PaymentIntent `kind=reissue_fee`,
idempotency key = request id, status → APPROVED_AWAITING_PAYMENT via new optional column, not a status-enum change),
`POST …/reject` (no charge). Webhook `kind=reissue_fee` → runs `admin_reset_token` with the stored new tag. Owner
override: `POST /admin/tags/:tagId/owner-override { newOwnerId, reason }` as a second RPC. Owner self-serve stays
`/nfc/reissue-request` only.

## Phase 3 outline

Stuck-payment queue (fee-succeeded + PENDING > N min), Re-apply (re-runs webhook apply, idempotent), admin-only refund,
~10-min sweep, GitHub Issues on suprMan21/auctionX (fine-grained token in 1Password + App Runner, dedup per transfer, IDs
only). Prices table (effective-dated) replacing `TRANSFER_FEE_CENTS`/`REISSUE_FEE_CENTS` env constants + vouchers.
