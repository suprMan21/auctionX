# S-2FA Ph3b — email-code recovery, backup email, security mail on SES

Branch `feature/s-2fa-ph3b` (worktree `.claude/worktrees/s-2fa-ph3b`). Covers S-2FAb AC7, AC13, AC14.
Flags stay off (Ph4 turns them on).

## Boss decisions (2026-10-27)

| Topic | Decision |
|---|---|
| Security mail | **Amazon SES** (no stored bodies). Postmark stays for every other mail. Codes never go through Postmark |
| Hold / freeze | 72 h hold, then 7-day freeze (Ph3 split decision) |
| Staff | **No email recovery for any staff account** (super_admin, admin, support). A staff member who loses every key: super_admin removes the role, they recover as a normal user, then the role comes back |
| Finish | After the hold, a **fresh email code** from the same inbox, then the person must add a passkey or authenticator app at once and gets a new set of backup codes |
| Old methods | **Kept**. Old backup codes are voided at finish. For the 7 days, signing in with an old method offers **Undo recovery**: removes what recovery added, signs out its sessions, makes new backup codes for the owner |
| Freeze blocks | Transfer start + accept, release, adding / removing sign-in methods, new backup codes, backup email changes, password / email change. Taps, viewing, disclosure stay open |

## Flow

1. Signed in with the password only (or through Supabase's reset link), on `/sign-in/verify`, the person picks
   **Can't use any of these?** → `/sign-in/recover`.
2. Chooses the account email or the backup email (both shown masked), gets a 6-digit code, types it.
3. A **72 h hold** starts. Every channel (account email + backup email) is told, with a plain "if this wasn't you,
   sign in with your passkey or authenticator app and cancel it". Any session that passed an existing method sees a
   banner on Security settings with **Cancel recovery**.
4. After the hold, back on `/sign-in/recover`: a fresh code to the same channel → **finish**. The session is marked
   verified (method `email_recovery`, 30 min), old backup codes are voided, a 7-day freeze starts.
5. The finishing session must add a passkey or authenticator app (no step-up: this is the one allowed add; it is
   tagged `added_by_recovery`). That gives new backup codes. Optional: set a new password once (a single
   `password` permit, because the Ph2b lock would otherwise refuse it).
6. During the freeze, a session that signs in with an **old** method sees **Undo recovery** (needs a step-up with
   an old passkey or authenticator app; never a recovery-added method, never a backup code).

Not allowed to start: staff accounts; accounts with no passkey or authenticator app (nothing to recover, just add
one); a session that already passed its second factor; while a recovery is holding; during a freeze.

## Email codes (AC13)

- 6 digits, 10-minute expiry, single use, 5 attempts per code, a new send voids the previous code.
- Bound to the Supabase `session_id` **and** a random nonce the browser keeps in localStorage and sends as
  `X-Recovery-Nonce` (stored as sha256). A code read from the inbox is useless in another session.
- Stored only as HMAC-SHA256 (key derived from `MFA_RECOVERY_PEPPER`, label `email-code-v1`) over
  `purpose | code id | user | session | code`. Purposes: `recovery_start`, `recovery_finish`, `backup_email_verify`.
- Sends: 60 s cooldown, 3 per hour, 10 per day per account (counted in the database), plus the existing per-IP
  code-check budget. Never logged (logs, errors, metrics). Code in the body only, never the subject.
- The email says we never ask for the code, and shows the browser + OS that asked.

## Backup email

One per account, must differ from the account email, verified with a code sent to it (purpose
`backup_email_verify`). Add / replace / remove needs a step-up (`recovery_channel`, passkey or any code like
`factor_add`) and is frozen during the freeze. Every change tells the account email (and the old backup address on
removal). Shown masked everywhere; never in logs.

## Security mail (SES)

- `lib/notifications/securityMailSender.ts`: `@aws-sdk/client-sesv2` `SendEmail`, simple content, no
  configuration set (no open / click tracking, no event destination). From = `SECURITY_MAIL_FROM`. Region =
  `SES_REGION` → `AWS_REGION` → `us-east-2`.
- Codes: SES only. Not configured → the send fails with "We can't send codes right now" (503). No fallback.
- The existing security notices (`mfaEmails.ts`: method added / removed, backup codes, break-glass alert, …) move
  to SES when it is configured, else stay on Postmark until it is (they carry no codes).
- Credentials: the default AWS chain. **App Runner has `AWS_ACCESS_KEY_ID` set (open item)**: env keys win over the
  instance role, so `ses:SendEmail` must be on whichever identity is actually used. Removing the env keys is better.

## API (`/api/v1/auth/mfa`)

| Method | Path | Notes |
|---|---|---|
| GET | `/status` | + `recovery` (status, hold end, freeze end, channel masked, `canUndo`), `backupEmail` (masked, verified) |
| GET | `/recovery` | Channels available (masked), current recovery, resend wait |
| POST | `/recovery/code` | `{ channel }` (start) or `{}` (finish, same channel). Needs `X-Recovery-Nonce` |
| POST | `/recovery/start` | `{ code }` → hold |
| POST | `/recovery/finish` | `{ code, setPassword? }` → freeze, session verified, may enrol once |
| POST | `/recovery/cancel` | Verified session (an existing method) |
| POST | `/recovery/undo` | Step-up `recovery_undo` with an old method |
| POST | `/backup-email` | Step-up `recovery_channel`; sends a verify code |
| POST | `/backup-email/verify` | `{ code }` |
| DELETE | `/backup-email` | Step-up `recovery_channel` |

Freeze: one helper `assertNotFrozen(userId)` in the MFA service + middleware `refuseWhileFrozen` on release,
transfer initiate, transfer accept. Reason `recovery_freeze` with `freezeEndsAt`.

## Frontend

`/sign-in/recover` (choose channel → code → hold countdown → finish code → add a method → optional new password),
link from `SecondFactorPage`. Security settings: backup email card, hold banner with Cancel, freeze notice with
Undo. `autocomplete="one-time-code"`, 60 s resend wait, plain copy (Brand Voice).
