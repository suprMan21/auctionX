# am-reissue-evidence-staging

Private bucket for re-issue evidence photos (S-ADMIN1 Ph2). An owner asking for a
replacement chip takes 1–3 photos of the chip still on the item with the web app's
live camera; admins view them in the re-issue queue.

**Why a separate bucket:** the media bucket `auctionx-media-prod-cl` serves every
object publicly by path (`PublicReadGetObject`, read 2026-10-09), and its
`verification/*` Deny blocks the backend too. Evidence never shares a bucket with
public media.

## How the backend uses it

| Step | Call | Permission |
|---|---|---|
| Owner asks to upload a photo | presigned `PutObject`, 5 min, `image/jpeg`, size signed | `s3:PutObject` |
| Owner submits the request | `HeadObject` per photo (exists, JPEG, ≤ 5 MB) | `s3:GetObject` |
| Admin opens the queue | presigned `GetObject`, 5 min | `s3:GetObject` |

Keys are always `reissue-evidence/<userId>/<uuid>.jpg`, generated by the backend.
Code: `backend/src/lib/reissueEvidence.ts`. Without `REISSUE_EVIDENCE_BUCKET` the
upload endpoint answers 503; it never falls back to the media bucket.

## Console setup (Boss, once) — us-east-2

1. **Create the bucket.** S3 → Create bucket.
   - Name `am-reissue-evidence-staging`, region **us-east-2**.
   - Object Ownership: **ACLs disabled**.
   - **Block all public access: ON** (all four boxes).
   - Default encryption: **SSE-S3**. Bucket Key on.
   - Versioning: off.
2. **Bucket policy.** Bucket → Permissions → Bucket policy → paste `bucket-policy.json`
   (HTTPS only).
3. **CORS.** Bucket → Permissions → CORS → paste `cors.json`. The browser PUTs straight
   to S3, so without this every upload fails with a CORS error. Add the production
   origin here at launch.
4. **Lifecycle.** Bucket → Management → Create lifecycle rule: name
   `expire-evidence-after-90-days`, prefix `reissue-evidence/`, expire current
   versions after **90 days** (`lifecycle.json` has the same rule).
5. **Backend access.** The backend signs S3 calls as IAM user **`auctionx-s3-access`**
   (its key is App Runner's `AWS_ACCESS_KEY_ID`; confirmed 2026-10-09 by matching the key
   under IAM → Users → Security credentials, since the console cannot search by key).
   On that user: Permissions → Add permissions → Create inline policy → JSON → paste
   `backend-access-policy.json`, name `ReissueEvidenceStaging`.
6. **App Runner env.** Add `REISSUE_EVIDENCE_BUCKET=am-reissue-evidence-staging`
   and deploy.

## Check (Claude can run these with `claude-ro` after step 1)

```bash
command aws --profile claude-ro --region us-east-2 s3api get-public-access-block --bucket am-reissue-evidence-staging
command aws --profile claude-ro --region us-east-2 s3api get-bucket-policy-status --bucket am-reissue-evidence-staging
```

Expect all four blocks `true` and `IsPublic: false`. (`claude-ro` needs the
`MediaBucketConfigReadOnly` statement extended to this bucket's ARN for these
reads; it can never read or list the photos themselves.)
