# SIM_PARITY — superseded by real AN12196 SDM (S-NFC3.5)

> **As of S-NFC3.5 (2026-10-01) this encoder no longer targets "simulator
> parity" with a simplified scheme.** The encoder, the backend verifier and the
> Tag HQ parser all implement genuine NXP AN12196 SDM (AES mode), and all three
> are pinned to ONE shared, OpenSSL-generated vector file.

## What changed

| | S-NFC2 Phase 1 (deleted) | S-NFC3.5 (now) |
|---|---|---|
| PICC key | static per-tag key | fleet-wide **SDMMetaReadKey** (K2, versioned) |
| PICC header | asserted `0xC7` | **PICCDataTag** parsed (UID + ctr mirrored, UID len 7) |
| MAC key | the same static per-tag key | **KSesSDMFileReadMAC** = CMAC(SDMFileReadKey (K3, per UID), SV2) |
| MAC input | the encrypted PICC block | the SDM MAC-input range (empty in our layout) |
| Truncation | first 8 bytes | **even-numbered bytes** (indices 1,3,…,15) |
| Compare | `===` | constant time |
| Key source | `LocalStubKeyProvider` (AES-CMAC KDF, hardcoded dev root) | HMAC root (KMS `GenerateMac` or local) → HKDF-Expand, two roots by role |
| ChangeFileSettings | `SDMMetaRead = 0xE` (plain mirror) | `SDMMetaRead = K2` (encrypted PICCData), `SDMFileRead = K3` |
| Fixtures | `tests/golden_vectors.json` + backend `__fixtures__/ntag424_vectors.json` (generated by our own code) | `test-vectors/ntag424_sdm_vectors.json` (generated by **openssl**) |

The old parity scaffolding (`tests/test_parity.py`, `tests/golden_vectors.json`,
the backend `__fixtures__` file and its test) is deleted.

## Where the spec lives

`docs/NTAG424_CRYPTO_REFERENCE.md` — byte layouts, key/slot map, verify order,
golden vector, file-settings layout.

## Regenerating vectors

```bash
python3 test-vectors/generate_ntag424_vectors.py   # needs OpenSSL >= 3.0
```

The script asserts OpenSSL reproduces AN12196's own example before writing.

## Live secure channel (S-NFC2 Phase 2, 2026-10-02)

Implemented in `tag_encoder/ntag424/session.py` and pinned to NXP AN12196
Rev 1.8 worked examples (Tables 8, 14, 18, 19, 26, 27) in
`tests/test_session.py`. The `apdu.py` "secured" helpers still raise
`RequiresLiveChannel` on purpose: a secured APDU only exists inside a live
`Session`. The physical flow is `tag_encoder/personalise.py`.
